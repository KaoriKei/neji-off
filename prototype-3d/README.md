# NEJI OFF — 六面のマット金属キューブ

360度回転できる六面のキューブから、18本のネジと6枚の外側パネルを外す一面。色トレイと一時置き場は、全6面で共有する。

## 起動

リポジトリのルートから実行する。

```sh
npm install
npm run dev -- --host 127.0.0.1 --port 5178
```

`http://127.0.0.1:5178/prototype-3d/` を開く。

```sh
npm run build:3d
```

3D試作だけを `prototype-3d/dist/` に出力する。既存の `npm run build` は従来のゲームを対象にする。

## 公開

- 通常版： https://kaorikei.github.io/neji-off/
- キューブ版： https://kaorikei.github.io/neji-off/cube/
- キューブ版の開発ブランチ：`feature/metal-cube`

GitHub Actions が `main` の通常版と `feature/metal-cube` のキューブ版をそれぞれ検証・ビルドし、ひとつのPages公開物にまとめる。どちらのブランチへのpushでも、両方のURLを維持して更新する。`main` に入れるのはこの公開処理の変更だけで、キューブ版のゲーム本体は専用ブランチで管理する。

キューブ版の公開中は専用ブランチを削除しない。ブランチ名を変える場合は、両ブランチの `.github/workflows/deploy.yml` と `github-pages` 環境の許可ブランチも変更する。

## 操作

- ネジをタップ：同色のトレイへ。空きがなければ5枠の一時置きへ。
- 同じ色が3本：トレイが交代し、一時置きにある同色のネジを回収する。
- パーツのネジを全部外す：そのパーツが外れる。
- キューブをドラッグ／左右の矢印：360度回転する。見えない裏面のネジを直接選ぶことはできない。
- 面番号の選択ボタンは置かず、ドラッグ・左右の矢印・「正面に戻す」で視点を操作する。
- 重なりを見る：外側のパネルを広げ、折り返した留め具の下のネジを確認する。確認中はネジを抜けない。
- 一手戻す：トレイの交代や連続回収を含めて前の状態に戻す。
- 最初から：盤面と履歴を初期化する。
- 最下段の商品紹介：タイヨウビス公式サイトを別タブで開く。

## 美術と範囲

- 基調は明るいグレー、マットシルバー、濃いグレーの金属。骨組みの接合部に少量の木を使う。
- ブランドのアクセント色は `#00AFCC`。ワッシャーは青・赤・紫・緑を使う。
- 既存のロジックで `yellow` と呼ぶ色を、試作では紫として表示する。既存ゲームの配色・データは変更しない。
- 穴・ネジ頭の十字溝・板の厚みは3D形状。材質、光、接触影で立体感を作る。
- 六面すべてにネジがあり、面をまたぐ折り返しの留め具が、隣の面のネジを覆う。上面を外すと正面と背面のネジが露出するなど、順番に意味がある。
- 内側の追加パズルはない。外側の6枚を外してクリアとする。
- 一時置き場は前回の平面試作の4枠から、今回は5枠に戻した。枠を減らさず、面同士のつながりで先読みを作る。
- 最下段に「タイヨウビス」「D6皿ドリル」「無溶接ビス」の紹介を置く。明るい金属の枠・ブルーのアクセント・ビスのイラストでゲームの見た目に合わせる。紹介先は https://taiyouvis.com/ 。
- 物理シミュレーションに勝敗を依存させず、確定したルールの結果を動きとして再生する。
- ネジを抜く動きは140ms、トレイへの飛行は260ms。同じ形状・材質の3Dネジを画面全体の描画層で曲線に沿って運び、到着時に正面向きと穴の大きさへ合わせる。盤面と飛行はひとつのWebGL描画器を共用する。
- パネルが外れる420msの動きはトレイの演出と並行する。パネルだけが動いている間は次のネジを抜けるが、一手戻す・やり直しはパネルが落ち着くまで待つ。
- 一時置きからの回収は1本180ms、開始を55msずつずらして重ねる。トレイ内の穴の幅はネジの有無で変えない。
- 見た目は生成モックアップを参考にした実際の3D表示。生成画像そのものを盤面として貼ってはいない。
- タッチ環境または `?light=1` では描画倍率を1にし、動的な影とアンチエイリアスを省く。通常の接触影は維持する。
- フォントはGoogle Fontsを利用し、取得できない場合はシステムフォントで表示する。

## 検証

```sh
npm test
node --import tsx scripts/verify-levels.ts
npm run build:3d
```

`cube-model.ts` が六面の向き・局所座標・留め具の関係を定義する。`choose-cube.ts` は5枠を前提に配色とトレイ順を探索する開発用スクリプト。採用した配置と正解手順は `cube-study.json` にある。

既存の `Board` に、任意の別パネルによる覆いを指定する `blockedBy` を追加した。指定のない従来のレベルは従来どおり座標で判定する。描画は `cube-renderer.mjs`、状態と履歴は `cube-puzzle.ts`、トレイ等の表示は `app.mjs` が担当する。

- 最小仮置き数は2枠。用意した枠は5枠。
- 素直な手順の自動プレイ300回（seed 36）では詰み率29%。人間の失敗率を表す数値ではない。
- テスト28件と、既存の全11面の検証が合格。
- ブラウザで番号ボタンを使わず、ドラッグで六面を回して18本すべてをクリア。5枠からの連続回収と一手戻すでの復元、パネルと隣の面の覆いの復元、やり直しを確認。
- ブラウザの390×844表示で、キューブ・5枠・商品紹介を含めて画面内に収まることを確認。
- 390×844の軽量表示でも3Dネジの飛行・着地・一手戻すを確認。トレイの穴の幅が着地前後で変わらないことと、ブラウザにエラー・警告がないことを確認。端末の実測フレームレートは未計測。
- Android実機での動作確認は未実施。

前回の平面試作の配置・ソルバー確認は `layout-study.json`、`choose-layout.ts`、`tests/Prototype3D.test.ts` に保持している。
